Assignment 1 — Local Git Practice

Build a small local repository that demonstrates every core Git operation from Module 1.

What to submit

  • Push your practice repo to your own personal GitHub account (public or unlisted).
  • Submit using the "Assignment 1 submission" issue form in the org (Issues → New issue → Assignment 1 submission) instead of pasting links in chat — it asks for your repo link and your git log --graph output directly.

Requirements

  • Repository initialized with git init
  • At least 3 commits with clear, imperative commit messages
  • At least 1 branch created, used, and merged back into main
  • One deliberately created and manually resolved merge conflict (edit the same line on two branches, merge, resolve by hand — don't let an editor auto-resolve it for you)
CriteriaPoints
Repo initialized correctly10
3+ meaningful commits with clear messages25
Branch created and merged correctly20
Merge conflict resolved by hand25
Submission link/screenshot is complete and readable20
Pairs with Module 2

Assignment 2 — Contribution Cycle

Run the full issue → branch → PR → review → merge cycle on your team's repo in CZMGC-SY202528, paired with a classmate.

What to submit

  • File the task using the "Contribution task" issue form in your team's repo (Issues → New issue) — it already asks for type, description, and team.
  • Open your PR — the description box is pre-filled with the What / Why / How-to-test template and a checklist, so you can't forget Closes #.
  • Then record both links on your completion certificate for grading.

Requirements

  • File one clear, labeled issue and assign it to your partner
  • Create a properly named branch (e.g. fix/<short-description>) — no direct commits to main
  • Open a PR with a description that includes Closes #<issue-number>
  • Leave at least two review comments on your partner's PR (one question:, one suggestion:)
  • Respond to review feedback with a follow-up commit before merge
CriteriaPoints
Clear, well-labeled issue20
Properly named branch (no direct commits to main)15
PR description links the issue20
Meaningful review comments left on a partner's PR25
Responded to feedback with a follow-up commit20
Reminder Branch protection on the team repo requires an approval before merge — you cannot skip the review step even if you wanted to.
